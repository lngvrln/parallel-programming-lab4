# parallel-programming-lab4

# MPI-паттерн — коллективные операции как основной механизм

Студент №7: v = ((7 − 1) mod 10) + 1 = 7.

## Запуск
    make full            # сборка + mpirun -np 4
    make full NP=8       # другое число процессов
Требуется MPI (OpenMPI или MPICH): `sudo apt install openmpi-bin libopenmpi-dev`.

## Задача
Вектор из N = 10 000 000 чисел: среднее, дисперсия, максимум, скалярное произведение x·y.

## Почему подходит этот паттерн
Задача — "раздать данные → посчитать локально → свернуть результаты". Это ровно то, что
делают коллективы: данные раздаёт `Scatterv`, параметры — `Bcast`, свёртку выполняют
`Allreduce`/`Reduce`. Дисперсии нужно глобальное среднее на каждом процессе, поэтому
здесь естественен `Allreduce`. Ручной цикл Send/Recv не нужен (в программе их нет), а
реализации коллективов в MPI используют деревья/рекурсивное удвоение: O(log P) шагов вместо O(P).

| Вызов | Зачем |
|---|---|
| MPI_Bcast | размер задачи N всем |
| MPI_Scatterv | куски x и y (N не кратно числу процессов) |
| MPI_Allreduce(SUM) | глобальные sum(x), dot(x,y) у всех |
| MPI_Reduce(SUM/MAX) | сумма квадратов отклонений, максимум на ранге 0 |
| MPI_Gather | размеры кусков для отчёта |

## Накладные расходы MPI
Вычисления здесь дешёвые (несколько операций на элемент), а `Scatterv` пересылает
2·N·8 байт = 160 МБ. Время передачи сравнимо или больше времени самих вычислений, поэтому
ускорение может быть < 1, особенно если процессов больше, чем физических ядер (все они
делят одну память и ядра). Ускорение растёт, когда работы на элемент больше (сложная
функция, много итераций) или данные уже лежат распределённо (генерируются на местах).
Плюс запуск процессов, `MPI_Init`, синхронизация (Barrier) и латентность коллективов.
